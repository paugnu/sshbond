# Terminal touch scrolling — 12 September 2026

The user confirmed build 11 fixes lock/resume, then reported uneven touch
scrolling through shell output. Public production submission remains paused.

The shipped xterm 5.3 touch handler applies each touch delta immediately and
allows the event to bubble when it reaches the scroll boundary. It has no touch
inertia. Upstream also documents iOS gesture problems, including scrolling when
the gesture starts over terminal text:
https://github.com/xtermjs/xterm.js/issues/3613
https://github.com/xtermjs/xterm.js/issues/594

A WebView-local handler now owns single-finger scrollback gestures in the normal
buffer. It prevents duplicate handling by xterm, groups scrollTop changes into
animation frames, keeps the drag at the boundaries, and applies bounded,
decaying inertia. Drag-generated clicks/mousedown events are suppressed so
scrolling does not also focus the terminal. Taps and small touch jitter remain
available to focus/type. A new touch, cancellation, window blur, or backgrounding
stops motion. Alternate-screen/mouse-reporting applications retain xterm's
existing handling. No keystrokes or SSH commands are generated by this handler.

Validation: TypeScript/lint and 169 Jest tests passed (16 suites). Gesture tests
execute the shipped JavaScript with controlled touch events, viewport and frame
clock; they cover batching, inertia, boundaries, tap-vs-drag, multi-touch and
background cancellation. They do not prove the feel of physical iPhone touch or
WebKit's native gesture arbitration. Recheck on the device with a long `ls -l`,
slow drags, flicks, top/bottom boundaries, keyboard open/closed and lock/resume.
